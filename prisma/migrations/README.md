# Migrations

Generated by Prisma, then **hand-edited** for what Prisma can't model (docs/08 §6.3). Every hand edit sits in a clearly marked section of the migration file.

## Workflow

```bash
pnpm db:local                                               # local Postgres on :5433 (keep running)
npx pnpm@12.6.0 exec prisma migrate dev --create-only --name <change>   # generate SQL only
# … edit prisma/migrations/<timestamp>_<change>/migration.sql …
pnpm db:deploy                                              # apply (non-interactive)
pnpm db:drift                                               # migrations ⇄ schema must report "No difference"
pnpm test:int                                               # constraints/triggers verified on a fresh DB
```

> Don't run plain `prisma migrate dev` from non-interactive shells (CI, agents): it can wait on a prompt forever and leave an orphaned `schema-engine` process holding file locks on Windows.

## Rules

- **Expand → contract** for breaking changes (docs/20 §4). Every production migration must work with the code that is currently running.
- Large-table indexes use `CREATE INDEX CONCURRENTLY` in their own migration. Start risky migrations with `SET lock_timeout = '5s';`.
- Anything created by hand that Prisma _can_ describe must also be declared in the schema (e.g. the trigram GIN indexes via `ops: raw("gin_trgm_ops")`). Otherwise the next generated migration will try to drop it. `pnpm db:drift` catches this.

## Hand-edited objects in `init`

| Object                                                                                                     | Why                                                                                                                                                  |
| ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `citext`, `pg_trgm` extensions                                                                             | Case-insensitive emails and coupon codes; fuzzy search                                                                                               |
| `analytics_events … PARTITION BY RANGE (occurred_at)` + default partition + `ensure_analytics_partition()` | Monthly partitions from day one (review R-19). A monthly job creates the next one and drops partitions older than 13 months                          |
| `order_number_seq` (starts 100001)                                                                         | Order numbers are assigned at payment (review R-12)                                                                                                  |
| ~60 `CHECK` constraints                                                                                    | Money consistency, ranges, state invariants (e.g. a paid order has a number and an email; `reserved ≤ on_hand`)                                      |
| Partial unique indexes                                                                                     | One default address/variant, one active cart per user, one active Stripe price per kind, one open return per order, reservation uniqueness per owner |
| `reject_mutation()` triggers                                                                               | `inventory_movements` and `audit_logs` are append-only                                                                                               |
| `product_search_vector()` + triggers                                                                       | Full-text search over name (A), subtitle (B) and ingredient names/aliases (C); refreshed when INCI changes                                           |
| Expression / partial indexes                                                                               | Available stock (`on_hand - reserved`), orders needing attention, failed webhooks, INCI trigram                                                      |

## Soft references

Actor and audit columns (`actor_id`, `created_by_id`, `moderated_by_id`, `initiated_by_id`, …) are **plain IDs without foreign keys**. This keeps history immutable, and anonymizing or deleting a user never fails because of years of audit rows. Ownership relations (orders → users, subscriptions → users, …) keep real foreign keys.
